# 通话文本分析场景（2026-11-03 新增）

> 业务上“真人接听”对应 `answer_recognize="否"`（`AnswerRecognizeType=1`）；
> “命中语音助手”才是 `"是"`（`AnswerRecognizeType=2`）。
> 时长参数单位为秒；日期格式 `YYYY-MM-DD HH:MM:SS`。
> `get_call_transcripts` 可直接带筛选条件导出，不必先查明细再导。


# 使用提示

- 提示词前缀统一为 **“使用 volc-aibot MCP：”**；
- 不确定工具能力时，先说「使用 volc-aibot MCP：调用 usage_guide 看看怎么用」；
- 涉及修改类操作（变量修改/赋值/发布）前，AI 会自动备份剧本与当前值到 result 目录；
- 对话测试会占用生产外呼资源，避免高峰时段大批量执行；
- 通话文本相关：
  - 真人接听用 `answer_recognize="否"`，命中语音助手用 `"是"`；
  - `duration_op` 支持 `大于等于/小于/介于`，数值单位秒；
  - `get_call_transcripts` 默认输出目录为 `result/{日期}/{时间_账号_查询通话文本}/{时间_uuid}/`，内含 `query.json`/`manifest.json`/`<通话ID>.md`；`analyze=true` 额外生成 `summary.json/summary.md`；
  - `limit` 为本次导出上限（MCP 默认 100），`workers` 默认 4，`skip_existing=true` 适合每日增量；
  - md 中机器人行带 `节点:节点名`，挂机等事件行以 `[事件]` 开头；`fetched`/`total` 为本次处理条数，`matched_total` 为命中总数；
  - 节点信息依赖通话 JSON 的 `node_name`：流程型/测试通话通常有；纯提示词或部分线上通话未采集时，md 无 `节点:`、summary 节点分布为空，此时按话术文本聚类近似归因并注明口径；
  - **当前版本不提供自动脱敏**（规则准确率不可控、对话可能因客户挂断不完整）；导出物含客户信息，请只在受控目录使用，报告中避免回显手机号/企业全称/金额；
  - 做前后对比时固定项目组、剧本、时间口径和筛选条件，避免口径漂移。
